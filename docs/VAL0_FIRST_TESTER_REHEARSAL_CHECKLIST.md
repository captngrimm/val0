# VAL0 FIRST TESTER REHEARSAL CHECKLIST

## Goal

Run one controlled founder-beta demo without overexplaining or overpromising.

## Before demo

Say:

This is raw founder beta. It is not a finished app and it is not magic.

The point is simple:
You can tell Val what is happening in your life or work, and she starts sorting it into useful memory and next steps.

## Boundary warning

Say:

Do not paste anything extremely sensitive yet.
This is still beta storage.
Val can help organize, remember structure, and draft messages.
Val does not send messages for you yet.
Val does not browse the web yet.
Val does not remember perfectly.

## Demo steps

### 1. Show onboarding

Run:

/onboardstatus

Explain:
This is the operating profile Val built from first contact.

### 2. Send messy story

Send:

Val, holy shit today was awful. Carlos called me twice because he still needs the solar quote. The supplier ghosted me again and now I look bad. Also save this idea: Val should track supplier follow-ups and warn me when a provider is becoming unreliable.

Explain:
This is the main idea. You do not need perfect commands. You can talk messy.

### 3. Show memory

Run:

/exosummary

Explain:
Val split the story into structured memory.

### 4. Ask for recovery

Run:

/whatnow

Explain:
Val uses profile + recent memory to suggest the next action.

### 5. Draft action

Run:

/draftfollowup

Explain:
Val turns the next action into a usable draft.

### 6. Capture future feature safely

Run:

/flowrequest Carpintero quiere monitorear herramientas nuevas de carpintería. Por ahora pegará newsletters o artículos y Val debe resumir qué aplica, si vale la pena, y cómo probarlo.

Explain:
If something is not built yet, Val should not fake it. She stores the request and gives a workaround.

## Questions to ask tester

1. Did this feel useful or just interesting?
2. What would you actually send Val tomorrow?
3. What felt confusing?
4. What felt fake?
5. What would make this worth $30/month?
6. What would make you stop using it?
7. Would you want Val for personal life, work, business, or all of it?

## Pass/fail criteria

PASS if tester says:
- I understand what this is.
- I can imagine using it.
- It feels raw but useful.
- I know what I would send it.

FAIL if tester says:
- This is just ChatGPT.
- I do not know what to do with it.
- I do not trust the memory/privacy.
- It feels like commands, not an assistant.

## After demo

Do not argue.

Capture feedback as:
- bug
- confusion
- feature request
- trust concern
- pricing concern
- workflow idea

Then decide whether to onboard them as tester or wait.
