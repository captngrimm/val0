# WISHLIST.md
VAL — Feature Intake Log

Purpose:
Record client feature requests without committing to delivery timeline.

This document is a logging mechanism, not a promise ledger.

---

## Core Rules

1. All feature requests are logged.
2. No feature is promised verbally or implicitly.
3. Wishlist entries do NOT modify the roadmap automatically.
4. Every entry must be categorized.
5. Every entry must receive a feasibility review before roadmap inclusion.
6. Price is not renegotiated based on wishlist items unless cost impact is confirmed.
7. Wishlist is reviewed only at end of sprint cycles.

---

## Categories (Required)

- Adjacent to roadmap
- Requires architectural change
- Requires new infrastructure
- Cosmetic only
- Regulatory / Compliance risk
- Performance impact

---

## Status (Required)

- Logged
- Under Review
- Accepted (Roadmap queued)
- Deferred
- Rejected

---

## Cost Impact (Required)

- None
- Minor (infra scaling)
- Moderate (dev time heavy)
- High (new services, APIs, licensing)
