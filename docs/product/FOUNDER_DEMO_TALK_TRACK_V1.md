# Founder Demo Talk Track V1

Purpose: give Frank a short, honest way to show Val0 in founder beta without selling magic.

## 30-Second Intro

Spanish:

> Val0 es una asistente personal por Telegram que empieza con un workflow real, no con promesas gigantes. Hoy la estoy usando para organizar agenda, tareas, calendario con confirmación, documentos de un caso, preguntas para la abogada y notas personales. Es founder beta: útil, guiada por humanos, y con límites claros.

English:

> Val0 is a Telegram-first personal operator. It starts with one real workflow instead of pretending to do everything. Today it can organize agenda, tasks, calendar drafts, a document/case workspace, lawyer-review questions, and personal folders. It is founder beta: useful, guided, and honest about limits.

## 2-Minute Demo Talk Track

Start with:

> I am not showing a public SaaS product yet. I am showing a working founder-beta operator around one real person/workflow. The point is: can Val reduce friction in real admin life without overstepping?

Then say:

> Watch the pattern. Val does small useful things, keeps boundaries, and asks for confirmation before sensitive actions. It is not legal advice, not perfect OCR, and not full autonomy. It is a guided operating layer that gets better by focusing on the workflows that actually matter.

Close the two-minute frame with:

> If this helps with one painful workflow this week, that is the product. We do not need to pretend it handles the whole universe on day one.

## Demo Sequence

### 1. Agenda

Before sending:

> First, I show the simple daily operator side. Can Val recover what is on my plate without me digging?

Send:

`Val, qué tengo mañana?`

Emphasize:

- Val answers in the current Telegram cockpit.
- This is practical continuity, not a dashboard demo.

### 2. Tasks

Before sending:

> Now I separate agenda from tasks. This matters because a real operator should not confuse pending work with appointments.

Send:

`Val, qué tareas activas tengo pendientes?`

Emphasize:

- Pending work is organized.
- It should not accidentally route into Caso Finca.

### 3. Calendar Draft With Confirmation

Before sending:

> For calendar actions, Val drafts first. It should not silently write sensitive actions.

Send:

`Val, agenda para mañana a la 1:30 PM cita con la bróker y mi mamá`

Emphasize:

- Calendar create stays behind confirmation.
- Stop before confirmation unless you intentionally want a real event.

### 4. Caso Finca Workspace

Before sending:

> Now the more valuable part: a real messy workflow. Caso Finca is not generic chat; it is a bounded workspace.

Send:

`Val, abre mi Caso Finca`

Emphasize:

- Read-only case dashboard.
- It organizes what Val has; it does not make legal conclusions.

### 5. Document List

Before sending:

> Next I show that documents are not just random uploads. They sit inside the case context.

Send:

`Val, muéstrame documentos del Caso Finca`

Emphasize:

- Documents are listed in a usable way.
- Normal view should not expose internal storage labels.

### 6. Document 1 Summary

Before sending:

> Now I ask for a summary of the first document. The important thing is that Val summarizes conservatively.

Send:

`Val, resume el documento 1`

Emphasize:

- It is an OCR-backed reading aid.
- It preserves a legal boundary.
- Nora/the lawyer confirms legal effect.

### 7. "Ves Algo Raro?" Bounded Q&A

Before sending:

> This is the trust test. I want Val to flag review points without pretending to be a lawyer.

Send:

`Val, ves algo raro?`

Emphasize:

- It should frame "focos/puntos para revisar con Nora".
- It must not say the case is won/lost.
- It must not claim certainty.

### 8. Folders / Libro

Before sending:

> Finally, Val is not only the case. It can also organize lightweight personal notes.

Send:

`Val, lista mis carpetas`

Then:

`Val, guarda esta idea en Libro: escribir una escena sobre el mercado`

Then:

`Val, qué tengo en Libro?`

Emphasize:

- Personal idea capture is separate from the case workspace.
- Duplicate exact notes should not keep multiplying.

## What To Emphasize

- Val starts with one real workflow.
- Val organizes real life/admin/case/business information.
- Val is useful before it is universal.
- Sensitive actions need confirmation.
- Legal/document answers stay bounded.
- Founder beta means human-guided setup and fast learning from real use.

## What Not To Promise

- No legal conclusions.
- No perfect OCR.
- No full autonomy.
- No public SaaS yet.
- No magic memory.
- No replacing lawyers, doctors, accountants, or professional reviewers.
- No guarantee that every requested integration is ready.

## How To Close The Demo

Say:

> The offer is not "buy an AI that does everything." The offer is: pick one workflow that is painful, set up Val around it, run it for a controlled first week, and see whether it saves friction. If it does, we expand carefully.

Then ask:

> What is the one workflow you keep losing track of right now?
