# PowerClub CRM Operativo + Dashboard Gerencial

## Pilot Proposal Draft V1

## 1. Positioning

This proposal describes a focused pilot, not a final production CRM.

The goal is to validate whether PowerClub can reduce lost commercial opportunities by improving follow-up visibility, advisor accountability, branch comparison, and management action.

The pilot should be scoped before implementation. Anything outside the approved scope becomes a change request or later phase.

## 2. Executive Summary

PowerClub may be losing sales, renewals, or reactivations when follow-up is late, unclear, or dependent on scattered files, manual reports, shift memory, or individual advisor habits.

The proposed pilot creates a lightweight CRM operating layer plus a management dashboard:

- Advisors get clearer daily follow-up workflow.
- Managers see overdue and stuck opportunities.
- Branch performance becomes visible.
- Source/channel quality becomes easier to compare.
- Management can prioritize opportunities that may still be protected.

This is not about selling "a CRM screen." It is about giving management operational visibility before opportunities are lost.

## 3. Current Problem / Assumed Operational Pain

Assumptions to confirm during discovery:

- Follow-up may happen across calls, messages, files, exports, and manual notes.
- Managers may not have a same-day view of overdue follow-ups.
- Advisor activity and advisor results may be hard to compare cleanly.
- Branch performance may be reviewed after the fact instead of during the month.
- Lead/source quality may not be obvious.
- Some interested prospects may get stuck without a next action.

Business risk:

```text
Weak follow-up can turn warm intent into lost opportunity.
```

## 4. Proposed Pilot

Build a scoped PowerClub CRM Operativo pilot with two connected layers:

1. Advisor/operator workflow.
2. Manager visibility dashboard.

The pilot starts with a scope freeze:

- Which branch/process is included.
- Which users/advisors are included.
- Which fields/statuses matter.
- Which dashboard view comes first.
- What reports/training/support are included.
- What is explicitly excluded.

## 5. MVP Scope

Recommended MVP:

- One defined pilot branch/process, or a tightly controlled multi-branch pilot.
- One primary manager dashboard preset.
- Core executive dashboard.
- Advisor daily workflow.
- Required statuses and follow-up rules.
- Basic import/export expectations if approved.
- Manager and advisor training.
- Three-month maintenance/support period.

## 6. Manager Visibility Dashboard

V1 dashboard areas:

- Executive KPI strip.
- Advisor activity ranking.
- Advisor result ranking.
- Pending follow-ups.
- Overdue follow-ups.
- Follow-up aging.
- Status distribution/funnel.
- Branch comparison.
- Source/channel performance.
- Daily/weekly activity.
- Stuck opportunities.
- Protected opportunity estimate.
- Manager action prompts.

Manager view options:

| Option | Best for | Decision supported |
| --- | --- | --- |
| Follow-up Control View | Branch managers / sales supervisors | Who must act today, what is overdue, what needs escalation |
| Advisor Performance View | General manager / sales lead | Coaching, support, recognition, workload review |
| Branch Comparison View | General manager / regional leadership | Which branch needs intervention |
| Recovery Opportunities View | Closing current-month opportunities | Which leads should be rescued first |

## 7. Operator Workflow

Advisor/operator workflow may include:

- Assigned lead/socio list.
- Status and management status.
- Last contact.
- Next action.
- Follow-up date.
- Notes.
- Plan offered.
- Branch/advisor ownership.
- History of interaction.

Purpose:

```text
Make the next action visible so follow-up does not depend on memory, the right file, or the previous shift.
```

## 8. Implementation Plan

### Phase 1 - Discovery And Scope Freeze

- Confirm branch/process.
- Confirm users and roles.
- Confirm fields/statuses.
- Confirm follow-up rules.
- Confirm first manager dashboard preset.
- Confirm reports and training.
- Confirm exclusions.

### Phase 2 - Build / Setup

- Configure pilot data model.
- Build agreed dashboard/workflow.
- Prepare import/export approach if included.
- Prepare training flow.
- Run internal review.

### Phase 3 - Training / Rollout

- Manager walkthrough.
- Advisor training.
- Pilot launch support.
- First feedback capture.
- Minor scoped adjustments.

### Phase 4 - Maintenance / Review

- Support agreed maintenance tier.
- Review dashboard usefulness.
- Track change requests.
- Decide expand, adjust, or stop.

## 10. Pricing Options

Pricing depends on final scope. Planning options:

| Option | Setup / development | Maintenance | Best fit |
| --- | --- | --- | --- |
| Founder-friendly / reduced pilot | $1,500-$2,500 | $300-$500/mo | Very narrow proof with limited branch/process, limited reports, limited support |
| Recommended pilot | $2,500 setup | $1,000/mo for 3 months | Serious pilot with training, dashboard tuning, and support |
| Corporate / expanded pilot | $4,000-$5,000+ | $1,200+/mo | Multiple branches, more users, heavier reporting/training expectations |

Recommended default to discuss after discovery:

```text
$2,500 setup + $1,000/month for 3 months
```

This can be adjusted based on final scope.

## 11. Maintenance / Support Model

Maintenance is separate from setup because a pilot needs support, training, adjustment, and decision-making after launch.

Possible maintenance tiers:

- Basic: $300-$500/mo for light support and minor adjustments.
- Pro: $750-$1,200/mo for active pilot support, dashboard tuning, training support, and monthly review.
- Expanded/managed: $1,500+/mo for broader rollout and heavier reporting cadence.

Maintenance does not include unlimited new development.

## 12. Exclusions

Not included unless separately scoped and priced:

- Real PowerClub data in demo materials.
- Payment integration.
- WhatsApp automation.
- Backend integrations beyond approved scope.
- Full SaaS/admin configurability.
- Custom mobile app.
- Unlimited reports.
- Production SLA.
- Full historical migration.
- Advanced permissions/auth.
- AI autonomy.
- Val PowerClub Copilot implementation.

## 13. Assumptions

- PowerClub will identify the pilot owner and decision-maker.
- PowerClub will confirm branch/process scope.
- PowerClub will confirm required fields/statuses.
- PowerClub will confirm training participants.
- PowerClub will approve exclusions and change request process.
- Demo numbers shown before production are fake/synthetic.

## 14. Decision Points

Before proposal approval:

- Which branch/process enters the pilot?
- How many users/advisors are included?
- Which manager view comes first?
- Which reports are included?
- Is import/export required in V1?
- Which maintenance tier is appropriate?
- Who approves change requests?

## 15. Val PowerClub Copilot Future Add-On

Val PowerClub Copilot can be discussed as a future/add-on layer, not a V1 core promise.

Possible later value:

- Managers ask questions about dashboard metrics.
- Copilot explains what metrics mean.
- Copilot suggests next questions.
- Copilot helps decide what to request or change.
- Copilot summarizes pilot feedback.

Boundaries:

- Separately scoped.
- Permissioned and transparent.
- Scoped to approved PowerClub knowledge.
- No full autonomy.
- No claim that Val already operates PowerClub.
