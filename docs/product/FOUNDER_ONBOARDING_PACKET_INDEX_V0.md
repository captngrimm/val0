## 2. When To Use Each Doc

### Before Conversation

Open:

- Founder Relationship / Roadmap Pitch
- Pricing / Founder Plan Boundaries
- Client-Facing Sales Copy

Goal:
Know the relationship frame, price boundary, and safe short language before talking.

### During Conversation

Open:

- Founder User Onboarding Script

Goal:
Explain the vision, boundaries, founder pact, and pick one workflow. Do not turn it into a full product demo or a "test everything" session.

### After Conversation

Open:

- Individual Roadmap Template
- Client-Facing Sales Copy

Goal:
Create the individual roadmap, send a short follow-up, and record the week-1 pilot terms.

### Before Demo

Open:

- Demo Smoke Checklist

Goal:
Verify the demo is safe, narrow, and honest. Do not demo with real sensitive documents unless consent and scope are clear.

### Week-1 Review

Open:

- Individual Roadmap Template
- Founder User Onboarding Script
- Pricing / Founder Plan Boundaries

Goal:
Review feedback, decide keep/adjust/pause/rescope, and catch upgrade triggers early.

## 3. Suggested Operator Flow

### 1. Prep

- Read the relationship pitch.
- Confirm this is personal founder use, not Val1 business.
- Review pricing boundaries.
- Decide whether a demo is needed.

### 2. Conversation

- Use the onboarding script.
- Explain: Telegram is the first cockpit, not the whole product.
- Explain: Val0 Personal is founder-beta.
- State limits plainly.
- Keep the tone warm and human.

### 3. Choose Workflow

Pick one narrow week-1 workflow:

- reminders/admin continuity
- legal/admin document organization
- grocery/list workflow
- meeting prep / next actions

Spanish operator line:

“No probemos todo. Escojamos un flujo real para esta semana y vemos si de verdad te ayuda.”

### 4. Create Individual Roadmap

- Copy the roadmap template.
- Fill only what is needed.
- Record privacy boundaries.
- Record 3-5 test prompts.
- Mark reusable ideas separately from custom requests.

### 5. Run Week-1 Pilot

- Use only the selected workflow.
- Avoid sensitive docs unless consent is explicit.
- Keep beta limits visible.
- Ask for concrete feedback.

### 6. Review Feedback

Capture:

- what helped
- what failed
- what felt confusing
- what they would use again
- what they do not want Val to do

### 7. Decide

Choose one:

- keep
- adjust
- pause
- rescope

If the user asks for business/team/custom/heavy support, move toward Val1 assessment or custom scope.

---

## 4. Decision Tree

### Personal Founder User

If:

- one person or family
- personal/admin continuity
- low support burden
- reusable product learning
- one guided workflow

Then:
Keep as Val0 Personal founder path.

### Business / Team / Process

If:

- multiple users
- customers, vendors, revenue, operations, or team workflow
- process ownership
- business support expectations
- workflow mapping beyond light personal use

Then:
Move to Val1 assessment.

### Sensitive / High-Risk

If:

- legal, medical, accounting, tax, financial, regulatory, or highly private data
- sensitive documents without clear consent
- high-risk automation
- professional decisions

Then:
Pause or scope carefully. State the professional boundary. Do not improvise.

### Unsupported Feature

If:

- perfect OCR/photo reading
- automatic DOCX extraction
- autonomous actions
- self-serve onboarding
- dashboards/portals
- custom integrations
- bulk migrations

Then:
Put it on roadmap, park it, or scope separately. Do not present it as included.

## 5. Minimal Founder-User Packet Checklist

Before the user starts week 1, confirm:

- [ ] Selected workflow
- [ ] Privacy boundary
- [ ] What they can send/upload
- [ ] What they should not send/upload
- [ ] Week-1 success criteria
- [ ] 3-5 test prompts
- [ ] Feedback date
- [ ] Custom/heavy work boundaries
- [ ] Professional-advice boundary if relevant
- [ ] Upgrade triggers noted

Short version:

“Un workflow, límites claros, 3-5 prompts, una fecha de feedback, y nada de prometer magia.”

---

## 6. Do-Not-Do List

Do not:

- create self-serve onboarding
- tell the user to test everything
- upload or request sensitive documents without consent
- promise unsupported OCR/photo/DOCX behavior
- imply autonomous actions
- imply professional legal/medical/accounting/tax/financial advice
- put business/team workflows under the $30 personal plan
- include unlimited custom work in founder pricing
- show raw paths, server internals, private IDs, tokens, or unrelated client data
- treat a demo smoke pass as production certification

---

## 7. Next Action After Packet Is Complete

Choose one:

- schedule the first real founder-user conversation
- create the first filled individual roadmap for a selected founder user

Recommended first move:

Pick one trusted personal founder user, run the onboarding conversation, choose one workflow, and create a sanitized individual roadmap before any week-1 pilot starts.

Operating principle:

Founder onboarding is guided, scoped, and relationship-based. The goal is useful real-world learning without pretending Val is self-serve, finished, or unlimited.
