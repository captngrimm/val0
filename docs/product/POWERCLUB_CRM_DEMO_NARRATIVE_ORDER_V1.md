# POWERCLUB CRM - Demo Narrative Order V1

## Purpose

Define the recommended presentation order for the PowerClub CRM Battle Stage so Frank can show a clear commercial story instead of walking through features in build order.

This is demo/discovery material only. It uses fictitious data, does not connect to real PowerClub systems, and does not promise production behavior.

## First-Screen Message

The opening should immediately answer:

- What problem the demo addresses.
- Who it helps.
- What to look at first.
- That all data is fictitious.
- That this is pilot/discovery material, not a production system.

Recommended opening line:

```text
Esta es una demo consultiva con datos ficticios para mostrar como PowerClub podria ganar visibilidad diaria sobre oportunidades, asesores, seguimientos y riesgo comercial antes de definir un piloto real.
```

## Three Questions The Demo Answers

1. What is happening with sales/follow-up?
2. Which advisors or branches need attention?
3. How can advisors work faster without a heavy CRM?

These questions should appear before operational details such as startup routine, channels, tools, files, and continuity.

## Recommended Demo Sequence

### 1. Opening / Purpose

Show:

- PowerClub CRM Battle Stage.
- Isthmus Dynamics / Honest AI Ops presenting brand.
- Demo with fictitious data.
- Pilot/discovery framing.

Say:

```text
No estamos viendo produccion ni datos reales. Estamos validando si esta visibilidad seria util para un piloto operativo.
```

### 2. Executive / Manager Dashboard First

Show:

- `Vista gerencial`.
- KPIs gerenciales clave.
- Fake-data notice.
- View presets only if useful.

Why:

Leadership first needs to understand operational visibility, not data entry.

### 3. Risk And Recovery Opportunities

Show:

- Risk/recovery KPIs.
- Overdue follow-ups.
- Stuck opportunities.
- Recovered/protected opportunity estimate as demo assumption.

Say:

```text
La pregunta no es si esta cifra es real; es si gerencia necesita ver que oportunidades estan en riesgo antes de perderlas.
```

### 4. Advisor Scorecard

Show:

- Ficha del asesor.
- Productivity and quality indicators.
- Coaching action prompt.

Frame:

Use coaching/accountability language, not punishment language.

### 5. Advisor Workflow / Next-Client Queue

Switch to:

- `Vista asesores`.

Show:

- Next client.
- Manual action buttons.
- Quick outcome buttons.
- Fast note.
- Follow-up date.
- Save and next.
- Mi progreso.

Say:

```text
El asesor no necesita un dashboard pesado. Necesita saber a quien contactar, que registrar y como pasar al siguiente sin friccion.
```

### 6. Communication Templates And Native Dictation

Show:

- Template selector.
- WhatsApp/manual message preview.
- Email subject/body preview.
- Copy message button.
- Native dictation hint.

Guardrail:

This does not send WhatsApp, email, or automated messages. It helps the advisor copy/send manually using approved tools.

### 7. Operational Context

Show lower context only after the executive and advisor story is clear:

- Inicio de turno.
- Current tools/channels.
- Continuity between shifts.

Why lower:

These details matter, but they should not be the first impression. The first impression should be executive value.

### 8. Val Copilot / AI Future Add-On

Show only if asked or near the end:

- Val PowerClub Copilot future section.
- KPI explanations.
- Manager questions.
- Weekly summaries.
- Coaching/risk prioritization.

Guardrail:

AI/Copilot is future/add-on only. It requires approved data sources, formulas, permissions, discovery, and scope freeze.

### 9. Discovery / Pilot Next Steps

Close with:

- Discovery meeting.
- Scope freeze.
- Pilot proposal.
- 30/60/90 rollout conversation.

Say:

```text
La siguiente decision no es construir todo. Es definir si hacemos discovery para congelar alcance y proponer un piloto controlado.
```

## What Moved Lower

Operational-context items should be below the executive story:

- Inicio de turno.
- Laptop/correo/Google Drive.
- Canales manuales.
- Continuidad entre turnos.
- File/tool context.

Reason:

They explain adoption and workflow, but they can make the opening feel scattered if shown before the dashboard value.

## First-Screen Guardrails

- Do not start with a feature list.
- Do not start with operational tool inventory.
- Do not imply production readiness.
- Do not imply real PowerClub data.
- Do not imply WhatsApp, email, payment, or AI automation.
- Do not frame the demo as "already built CRM."

## Talk Track Summary

```text
Primero mostramos visibilidad para gerencia.
Despues mostramos riesgo y oportunidades que podrian rescatarse.
Luego mostramos como se inspecciona un asesor.
Despues bajamos al flujo diario del asesor.
Finalmente hablamos de plantillas, dictado nativo, IA futura y discovery.
```
