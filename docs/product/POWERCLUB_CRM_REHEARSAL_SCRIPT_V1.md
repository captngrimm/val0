# POWERCLUB CRM - Rehearsal Script V1

## Purpose

Give Frank a simple, repeatable talk track for Karen review, boss/GM demo, discovery, and pilot close.

Tone:

- Calm.
- Consultative.
- Operational.
- No hype.
- No production promise.

Core sentence:

```text
No estamos vendiendo "un CRM" como pantalla bonita. Estamos validando un piloto para que gerencia vea seguimiento, asesores, sucursales, riesgos y oportunidades antes de que se pierdan.
```

## 60-Second Pitch

```text
Karen, lo que prepare no es un CRM final ni usa datos reales. Es una demo de piloto para visualizar el problema operativo: cuando los seguimientos se atrasan o dependen de archivos y memoria, se pierden oportunidades.

La idea es mostrar dos lados: gerencia ve que esta pasando por asesor, sucursal, fuente y riesgo; y el asesor tiene una cola simple para saber a quien contactar, que decir, que resultado marcar y como avanzar al siguiente.

Si esto se siente alineado con el dolor real de PowerClub, el siguiente paso no es prometer todo. Es discovery, congelar alcance y armar una propuesta de piloto de tres meses.
```

Stop and ask:

```text
Antes de mostrar mas, ¿este dolor suena correcto o estoy apuntando al problema equivocado?
```

## 5-Minute Karen Review Script

Minute 0-1: frame safely.

```text
Esto es demo/mockup con datos sinteticos. No esta conectado a PowerClub, no envia WhatsApp, no maneja pagos y no es produccion.
```

Minute 1-2: show executive dashboard first.

```text
Empiezo por gerencia porque el valor comercial es visibilidad. Aqui la conversacion no es "tenemos una lista"; es "sabemos donde hay seguimiento atrasado, que asesor necesita apoyo y que sucursal requiere atencion".
```

Minute 2-3: show risk and KPI explanation.

```text
Si alguien pregunta que significa un KPI, se puede abrir y explicar formula demo, datos usados y accion sugerida. Eso evita que el dashboard parezca inventado.
```

Minute 3-4: show advisor workflow.

```text
Del otro lado, el asesor no necesita un dashboard pesado. Necesita siguiente cliente, boton de llamada/manual, plantilla para copiar, nota rapida, resultado y guardar/siguiente.
```

Minute 4-5: ask for Karen alignment.

```text
Lo que necesito de ti es criterio comercial: ¿esto representa bien el dolor? ¿Que ajustarias antes de mostrarlo al jefe o gerente general? ¿Lo ves suficientemente claro para abrir una reunion?
```

Stop talking after the question. Let Karen react.

Close for Karen:

```text
Si te parece fuerte, el siguiente paso seria que me ayudes a validar quien debe estar en la reunion y que punto debo cuidar para no prometer de mas.
```

## 10-Minute Boss / GM Demo Script

Minute 0-1: opening.

```text
Gracias por el espacio. Esto es una demo consultiva de piloto, no un sistema final. Usa datos ficticios para mostrar que visibilidad podria tener gerencia si luego aprobamos datos, reglas y alcance.
```

Minute 1-2: pain.

```text
El problema que estamos atacando es simple: seguimiento debil significa oportunidades perdidas. Si gerencia no ve atrasos, ritmo por asesor, sucursales y fuentes, se entera tarde.
```

Minute 2-4: executive dashboard.

Show:

- KPIs gerenciales clave.
- Riesgo/recuperacion.
- Branch/source sections.
- KPI drawer for one metric.

Say:

```text
Esto no pretende reportar la realidad de PowerClub hoy. Pretende mostrar el tipo de control diario que un piloto podria habilitar.
```

Minute 4-6: advisor accountability without punishment.

Show:

- Advisor scorecard.
- Advisor productivity.

Say:

```text
Esto no es para castigar asesores. Es para coaching y foco: quien necesita apoyo, que seguimiento esta atrasado y que oportunidad todavia se puede rescatar.
```

Minute 6-8: advisor workflow.

Switch to `Vista asesores`.

Show:

- Next-client queue.
- Quick outcomes.
- Communication template.
- Native dictation hint.
- Save and next.
- Mi progreso.

Say:

```text
El asesor no debe pelear con el sistema. La vista operativa tiene que ser rapida: copiar mensaje, contactar manualmente, dictar o escribir una nota, marcar resultado y pasar al siguiente.
```

Minute 8-9: scope guardrails.

```text
V1 no incluye WhatsApp automatizado, pagos, datos reales sin aprobacion ni cambios ilimitados. Eso protege el piloto y evita vender algo imposible de mantener.
```

Minute 9-10: ask and close.

```text
Mi pregunta no es si quieren todo hoy. Mi pregunta es: ¿vale la pena hacer discovery para definir un piloto controlado con una sucursal/proceso, campos aprobados, reportes claros y mantenimiento separado?
```

Stop talking.

## 15-Minute Discovery Conversation Script

Minute 0-2: confirm pain.

Ask:

- "¿Donde se pierde mas seguimiento hoy?"
- "¿Que reporte pide gerencia que hoy cuesta armar?"
- "¿Que decision quisieran tomar cada manana?"

Minute 2-5: define pilot shape.

Ask:

- "¿Que sucursal o proceso deberia entrar primero?"
- "¿Cuantos asesores entrarían al piloto?"
- "¿Quien usaria la vista gerencial?"
- "¿Quien usaria la vista asesor?"

Minute 5-8: define data and fields.

Ask:

- "¿De donde sale la base hoy?"
- "¿Que campos son obligatorios?"
- "¿Que estados usan realmente?"
- "¿Que significa atrasado para ustedes?"
- "¿Podemos revisar un export/muestra aprobada?"

Minute 8-11: define dashboards and workflow.

Ask:

- "¿Cual vista gerencial es prioritaria: seguimiento, asesores, sucursales o rescate?"
- "¿Que debe ver el asesor y que no debe ver?"
- "¿Quieren plantillas de mensajes aprobadas?"
- "¿Que reportes son obligatorios y cuales pueden esperar?"

Minute 11-13: define exclusions.

Say:

```text
Para que el piloto funcione, tambien hay que decir que NO entra.
```

Confirm:

- WhatsApp automation out of V1.
- Payments out of V1.
- Final production CRM out of V1.
- Unlimited reports out of V1.
- Copilot/AI as future add-on only.

Minute 13-15: decision path.

Ask:

- "¿Quien aprueba alcance?"
- "¿Quien aprueba presupuesto?"
- "¿Cual fecha importa?"
- "¿Les parece agendar scope freeze y preparar propuesta de piloto?"

## When To Show Each Part

Show executive dashboard:
At the beginning. Leadership buys visibility before they buy workflow.

Show advisor workflow:
After the executive pain is clear. Use it to prove adoption is practical.

Show communication templates:
When they ask how advisors would work faster. Emphasize manual copy/send.

Show pricing/scope:
Only after they agree the pain is real or ask directly about cost.

Show AI/Copilot:
Only if they ask, or near the end as future evolution. Keep it add-on.

Stop talking and ask questions:

- After the 60-second pitch.
- After showing the executive dashboard.
- After showing advisor workflow.
- Before pricing.
- After any objection answer.

## Pricing Talk Track

Use this only when the room is ready:

```text
No quiero cotizar infinito. Lo sano es separar setup/desarrollo, implementacion/training y mantenimiento. Despues de discovery congelamos sucursales, usuarios, campos, reportes y exclusiones; con eso se arma la propuesta.
```

If they want a range:

```text
Hay una opcion reducida, una recomendada de piloto y una expandida. El precio depende de alcance, soporte y mantenimiento. Prefiero confirmar alcance antes de fijar numero.
```

If they push:

```text
Como referencia, se puede pensar en setup/desarrollo mas mantenimiento mensual por tres meses, pero no lo cerraria sin scope freeze.
```

## Closing Lines

### Karen Review Close

```text
¿Esto se siente alineado con lo que PowerClub realmente necesita ver? Si si, dime que ajustarias antes de ensenarlo arriba.
```

### Boss Meeting Close

```text
Si la direccion hace sentido, la decision hoy no es construir todo. La decision es si hacemos discovery para definir un piloto controlado.
```

### Discovery Scheduling Close

```text
Propongo una sesion corta de discovery con Karen, gerencia/operaciones y quien maneje los datos. De ahi salimos con alcance, exclusiones y propuesta.
```

### Pilot Proposal Follow-Up Close

```text
Con discovery cerrado, preparo una propuesta de piloto con tres partes separadas: setup/desarrollo, implementacion/training y mantenimiento mensual.
```

## Do Not Say

- "Esto ya opera PowerClub."
- "Estos son sus numeros reales."
- "Ya esta listo para produccion."
- "WhatsApp automatico esta incluido."
- "Pagos estan incluidos."
- "La IA ya decide por gerencia."
- "Cualquier cambio entra sin costo."
- "No hace falta discovery."

## Rehearsal Checklist

Before the meeting, Frank should practice:

- 60-second pitch without screen.
- 5-minute Karen version.
- 10-minute boss/GM version.
- One objection answer for price.
- One objection answer for WhatsApp.
- One objection answer for AI.
- One transition from dashboard to advisor workflow.
- One close that asks for discovery, not immediate production.

## Guardrails

- Fake data/demo framing stays visible.
- No real PowerClub data.
- No final production promise.
- No WhatsApp/payment integration promise.
- No unlimited customization.
- No claim Val already operates PowerClub.
- AI/Copilot remains future/add-on unless separately scoped.
- Scope freeze comes before proposal.
