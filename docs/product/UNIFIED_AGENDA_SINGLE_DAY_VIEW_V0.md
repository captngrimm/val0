# UNIFIED_AGENDA_SINGLE_DAY_VIEW_V0

Purpose:
Design a unified agenda / single-day view for Val0 / Valdia, with Karen/client-zero founder-beta as the first practical reference.

This is a product/design document only. It is not runtime config, not a bot route, not a calendar integration change, and not a promise that unified agenda is ready for Tuesday founder-beta delivery.

Tone:
Spanish-first examples, product-safe, operator-ready, honest, concise, practical.

---

## 1. Purpose

Unified Agenda should let a user ask one simple question and see the useful day view across calendar, reminders, documents, tasks, legal/finca actions, and follow-ups.

It should help answer:

- what is scheduled today
- what is scheduled tomorrow
- what is overdue
- what needs review
- what follow-up is waiting
- what the next useful action is

The goal is not to merge every source into one vague list. The goal is a single human view with clear source labels:

```text
Eventos confirmados separados de recordatorios, pendientes y cosas que requieren revisión.
```

---

## 2. Problem

Today-style answers can be fragmented because the user's day may live across separate sources:

- Google Calendar events
- internal reminders
- tasks
- documents
- legal/finca actions
- follow-ups after meetings

Without a unified day view, the user may have to ask multiple questions:

```text
Val, qué tengo hoy?
Val, qué recordatorios tengo?
Val, qué documentos faltan?
Val, qué tengo pendiente de la finca?
Val, qué pasó después de la reunión?
```

This creates three risks:

- important actions are missed because they live in another source
- uncertain document/review items are presented like confirmed calendar events
- agenda answers become too long or technically noisy

Unified Agenda should reduce context switching while staying honest about source and certainty.

---

## 3. Desired User Experience

Spanish-first prompts to support eventually:

- `Val, ¿qué tengo hoy?`
- `Val, ¿qué tengo mañana?`
- `Val, ¿qué sigue?`
- `Val, qué está vencido?`

Useful variants:

- `Val, qué tengo para hoy`
- `Val, qué hay mañana`
- `Val, cuál es el próximo pendiente`
- `Val, qué me falta revisar`
- `Val, qué agenda tengo`

Expected behavior:

- answer with a compact day view
- group by source/category
- show confirmed events before softer pending items
- mark overdue/review-needed items clearly
- suggest one next action when useful
- avoid creating, deleting, or editing anything during a read-only query

Example compact answer:

```text
Hoy:

Eventos confirmados:
1. [Google Calendar] 10:00 - cita con Mabel.

Recordatorios:
1. [Val] Revisar pendiente de Finca.

Pendientes / revisión:
1. [Documento] Finca 10082 - requiere revisión.
2. [Documento] Foto de Finca - requiere OCR antes de resumir.

Siguiente acción sugerida:
Revisar primero el documento marcado como pendiente antes de hablar con Nora.
```

## 4. Source Categories

### Google Calendar

Confirmed calendar events from connected calendar sources.

Display as:

```text
[Google Calendar] 10:00 - cita con Mabel
```

Rule:
Do not treat Google Calendar reads as permission to create/delete/edit events.

### Internal Reminders

Val-created or Val-tracked reminders.

Display as:

```text
[Val recordatorio] Llamar para confirmar cita
```

Rule:
If stale or overdue, mark it instead of presenting it as fresh.

### Tasks

General tasks or pending items not necessarily tied to a calendar time.

Display as:

```text
[Pendiente] Preparar preguntas para Nora
```

Rule:
Tasks are not hard events unless they have a confirmed date/time.

### Legal / Finca Actions

Actions related to legal/admin/finca continuity.

Display as:

```text
[Finca] Revisar documento finca 10082
```

Rule:
Do not turn a legal/admin label into a legal conclusion.

### Document Review Actions

Items generated by document status, such as unreadable, OCR-needed, or manual-review-needed documents.

Display as:

```text
[Documento] Foto de Finca - requiere OCR/manual review
```

Rule:
Never pretend an OCR-needed file is understood.

### Follow-Ups After Meetings

Items captured after a call, appointment, lawyer conversation, advisor meeting, or operator check-in.

Display as:

```text
[Follow-up] Enviar pregunta pendiente a Nora
```

Rule:
If follow-up source is unclear, label it as pending/review rather than a confirmed event.

## 5. Suggested Output Format

Use a predictable order:

1. Today / Tomorrow header
2. Hard events
3. Reminders
4. Pending actions
5. Overdue / needs review
6. Suggested next action

Template:

```text
Hoy:

Eventos confirmados:
- [source] time/title

Recordatorios:
- [source] reminder

Pendientes:
- [source] action

Vencido / requiere revisión:
- [source] item/status

Siguiente acción sugerida:
- one practical next step
```

If empty:

```text
Hoy no veo eventos confirmados. Sí puedo revisar pendientes o documentos si quieres.
```

If uncertain:

```text
Veo esto como pendiente, no como cita confirmada: [item].
```

If too many items:

```text
Hay varios pendientes. Te muestro los 3 más importantes y puedo abrir el resto si quieres.
```

## 6. Karen Examples

These examples are product-safe patterns. Do not store private legal facts, raw document names, local paths, IDs, or detailed case history here.

### Cita Topografo

Display:

```text
[Google Calendar] 9:00 - cita topógrafo
```

If source is internal reminder only:

```text
[Val recordatorio] Confirmar cita topógrafo
```

Safety:
Do not present the internal reminder as a confirmed Google Calendar event.

### Cita Con Mabel

Display:

```text
[Google Calendar] 10:00 - cita con Mabel
```

If time is missing:

```text
[Pendiente] Cita con Mabel - falta confirmar hora
```

Safety:
Missing time means it should not be treated as a hard event.

### Revisar Documento Finca 10082

Display:

```text
[Documento/Finca] Revisar documento finca 10082
```

Possible status:

```text
Estado: recibido, revisión pendiente.
```

Safety:
This is a review action, not a legal conclusion.

### Hablar Con Nora

Display:

```text
[Follow-up legal] Preparar preguntas para hablar con Nora
```

Suggested next action:

```text
Preparar 3 preguntas y tener a mano los documentos marcados como revisión pendiente.
```

Safety:
Do not provide legal advice or imply that Val decides legal strategy.

### Documento Necesita OCR / Manual Review

Display:

```text
[Documento] Foto de Finca - requiere OCR/manual review
```

Suggested next action:

```text
Primero revisar o extraer texto antes de agregarlo a cronología.
```

Safety:
Do not summarize or timeline an unreadable document as if it were already understood.

## 7. Safety Rules

- Read-only agenda queries must not create, delete, edit, or reschedule anything.
- Source labels must be visible.
- Distinguish Google Calendar from Val internal agenda.
- Avoid pretending uncertain items are confirmed events.
- Separate hard events from reminders, tasks, and review-needed items.
- Mark stale/overdue reminders honestly.
- Do not infer legal conclusions from agenda placement.
- Do not expose raw IDs, local paths, private filenames, chat IDs, or cross-client data by default.
- Do not merge duplicate-looking items unless source identity is preserved.
- Do not silently convert a document action into a calendar event.
- Preserve Karen Tuesday founder-beta stability; this doc does not change runtime behavior.

Safe line:

```text
Esto lo veo como pendiente, no como cita confirmada.
```

## 8. Future Runtime Notes

No runtime behavior is implemented by this document.

Later implementation should consider:

- merge sources into one ordered day view
- preserve source IDs internally
- hide technical IDs from normal user answers
- avoid duplicate display across Google Calendar and Val reminders
- keep event/reminder/task/document-action types distinct
- sort hard events by time
- group untimed actions below timed events
- mark overdue items separately
- support `mark done` later
- support source-aware detail drilldown later
- use client identity resolver and client-aware source filtering
- keep action creation behind explicit confirmation

Possible internal shape:

```yaml
agenda_item:
  item_id: "internal_or_source_id"
  client_id: "client_alias_or_id"
  source: "google_calendar | val_reminder | task | document | follow_up"
  display_title: "cita con Mabel"
  date: "2026-05-25"
  time: "10:00"
  certainty: "confirmed | pending | needs_confirmation | overdue | needs_review"
  source_label: "Google Calendar"
  domain_labels:
    - "agenda"
  action_labels:
    - "review with Karen"
  linked_folder: "Finca"
  privacy_notes:
    - "Do not expose source IDs by default."
```

Phases:

1. Design-only single-day view.
2. Manual/operator examples in docs.
3. Read-only source-labeled agenda rendering.
4. Deduplication and source-preserving merge.
5. Mark done / snooze / reschedule with explicit confirmation.
6. Cross-link with documents, folders, and Roadmap Answer Mode.

## 10. Product Principle

Unified Agenda is a view, not an action engine.

Good Unified Agenda behavior:

- shows confirmed events first
- keeps source labels visible
- separates reminders, pending actions, and review-needed documents
- gives one useful next step
- stays honest about uncertainty

Bad Unified Agenda behavior:

- creates or edits items during a read-only query
- hides whether something came from Google Calendar or Val
- treats every pending as a confirmed event
- duplicates the same item in multiple sections
- implies legal conclusions or unsupported automation

Operator line:

```text
Primero te muestro el día en una sola vista. Lo confirmado va arriba; lo pendiente y lo que requiere revisión va separado.
```
