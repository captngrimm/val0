## 2. When To Use Each Doc

### Before Assessment

Open:

- Val1 Assessment Script
- Client-Facing Sales Copy
- Val0 / Val1 Offer Architecture

Goal:
Confirm this is business/process pain, set expectations, and avoid selling automation before mapping the workflow.

### During Assessment

Open:

- Val1 Assessment Script

Goal:
Run the 45-60 minute call, map the workflow, ask discovery questions, surface risks, and choose 1-3 candidate workflows.

### After Assessment

Open:

- Val1 Assessment Summary Template
- Pricing / Founder Plan Boundaries

Goal:
Fill the deliverable, score candidate workflows, recommend a package or no-fit/defer/custom path.

### When Recommending $300/Month Package

Open:

- Pricing / Founder Plan Boundaries
- Client-Facing Sales Copy
- Val0 / Val1 Offer Architecture

Goal:
Explain what the Val1 base package includes, what it excludes, and why the workflow has enough value for month 1.

### When Custom Scope Is Needed

Open:

- Pricing / Founder Plan Boundaries
- Val1 Assessment Summary Template

Goal:
Mark integrations, dashboards, migrations, team workflows, high-risk data, SLA expectations, or heavy support as separate scope.

### When No-Fit / Defer Is Appropriate

Open:

- Val1 Assessment Summary Template
- Founder Beta Package

Goal:
Explain why not to proceed now: vague workflow, low value, high risk, unsupported feature dependency, or unclear owner/decision path.

## 3. Operator Flow

### 1. Prep

- Confirm the prospect is business/process oriented.
- Gather business/category placeholders.
- Note current pain hypothesis.
- List known tools.
- Identify likely privacy/risk concerns.
- Write down what not to promise.

### 2. Assessment Call

- Set frame: clarity and scope, not automation.
- Explain Val1 as business offer route on the same Val operating layer.
- Walk through one real workflow.
- Map tools, people, handoffs, decisions, follow-ups, and source of truth.
- Surface privacy/risk boundaries.

Spanish operator line:

“La meta hoy no es automatizar. Es entender el proceso real para decidir si Val puede ayudar, dónde, y con qué límites.”

### 3. Score Candidate Workflows

Score 1-3 workflows for:

- value
- simplicity
- risk
- reusability
- data sensitivity
- integration burden
- support burden
- founder-beta fit

### 4. Choose Recommendation

Choose one:

- Val0 Personal
- Val1 Business $300/month base
- custom scope
- defer / later fit
- no fit

### 5. Fill Summary Template

- Keep it concise.
- Do not paste raw sensitive notes.
- Include workflow map, pain points, month-1 roadmap, risk boundaries, and recommendation.

### 6. Send Follow-Up

- Use the summary template's WhatsApp-style message.
- Name what was identified.
- Name what will be delivered next.
- Repeat unsupported-promise boundaries.

### 7. Decide Next Step

- If Val1 base: define first workflow and schedule setup/check-in.
- If custom: scope separately.
- If defer/no-fit: name revisit condition.
- If personal: route to Val0 Personal packet instead.

## 4. Decision Tree

### Val0 Personal

Choose if:

- one person/family
- personal/admin continuity
- low support burden
- no business/team/customer/vendor process
- no integrations or operational ownership expected

Next:
Use founder-user onboarding packet instead.

### Val1 Business $300/Month Base

Choose if:

- business workflow is clear
- 1-3 workflows can be piloted
- value is visible in month 1
- support is weekly/biweekly and light
- privacy/risk is manageable
- integrations are not required for the first useful version

Next:
Define first workflow, confirm scope, and schedule guided setup/check-in.

### Custom Scope

Choose if:

- integrations are required
- dashboard/client portal is required
- data migration or bulk cleanup is required
- team permissions are required
- support burden is heavy or urgent
- workflow touches high-risk data
- SLA/uptime expectations exist

Next:
Pause base package recommendation and quote/scope separately.

### Defer / Later Fit

Choose if:

- workflow is interesting but not ready
- owner/decision path is unclear
- data boundaries need review
- integration dependency should be solved later
- value is plausible but not month-1 clear

Next:
Document revisit trigger.

### No Fit

Choose if:

- workflow is too vague
- value is too low
- risk is too high for founder-beta
- client expects finished SaaS, autonomous employee, or full integrations now
- client needs professional advice, not workflow support

Next:
Say no clearly and preserve trust.

## 5. Minimal Assessment Checklist

Before the assessment is considered complete:

- [ ] Workflow mapped
- [ ] Top pain points identified
- [ ] Current tools listed
- [ ] People/roles/handoffs captured
- [ ] Current source of truth identified
- [ ] Privacy/risk boundaries captured
- [ ] Candidate workflows scored
- [ ] Month-1 success criteria defined
- [ ] Package recommendation selected
- [ ] Explicit exclusions stated
- [ ] Follow-up/deliverable sent or scheduled

Short version:

“Mapa del flujo, dolores, herramientas, riesgos, workflows candidatos, éxito de mes 1, recomendación, y límites claros.”

---

## 6. Do-Not-Do List

Do not:

- implement during the assessment
- promise automation
- claim uptime/SLA
- include full integrations by default
- promise unsupported OCR/DOCX behavior
- claim professional advice replacement
- claim enterprise/team security unless implemented
- create a client profile/runtime setup from this doc
- create real client folders before scope/consent
- store private business data in product docs
- sell dashboards or migrations as included in the base package
- present Val1 as a separate platform
- say “Val will run your business”

## 7. Next Action After Packet

Choose one:

- fill the first real assessment summary after a real call
- create a client-specific folder only after scope and consent

Recommended first move:

Run one real $150 assessment using the script, then fill the summary template with sanitized, client-approved scope. Do not create runtime setup until the recommendation is confirmed.

Operating principle:

Val1 assessment should sell clarity. Implementation comes only after fit, scope, risk, and boundaries are explicit.
